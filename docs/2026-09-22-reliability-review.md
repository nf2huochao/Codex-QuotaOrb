# 可靠性与体验评估 / 2026-09-22

本轮范围：任务发现与状态更新、额度兼容与错误提示、桌面/局域网刷新和配对流程。保持现有外观与安装配置，不发布远端发行版。

## 已确认的问题与修复设计

- 会话按文件修改时间过滤，Windows 上持续追加而修改时间不变的任务被排除。改为发现文件后检查长度变化、增量解析完整记录，以记录时间判断新鲜度；单次读失败保留短暂宽限。
- 增量读取丢弃未写完的 JSON 尾行。仅推进到完整换行边界，下次继续读取。
- 统计记录会把已完成任务重新置为运行；等待输入的工具调用未识别。使用明确生命周期与工具名解析，统计记录仅更新用量。
- 额度刷新使用陈旧的完整快照，覆盖实时任务。以原子局部更新发布额度，任务扫描独立合并；完整刷新并行读取额度与用量。
- 接口所有未知错误都显示协议不兼容。仅在明确不支持方法/参数时这样分类，区分服务不可用、登录、网络、格式错误；兼容按额度 ID 返回以及小数百分比。
- 手机端重新配对未始终绑定提交事件，断网提示可被旧响应排序挡住，刷新成功只看 HTTP 成功。修正配对重试、网络超时与成功条件。
- 英文 Token 仍用万/亿，长错误文本截断。补齐英文数字显示、错误本地化与可读的换行反馈。
- 更新检查原先会直接下载并安装；现在先展示版本，再由用户确认安装。
- 四位配对码原先可无限尝试，重置配对后旧网页连接仍可能继续收取更新。限制一分钟内连续失败次数，重置后关闭旧连接。
- Codex CLI 在软件运行期间被升级或搬迁后，重连循环继续使用启动时的旧路径。每次重连前重新发现可执行文件。
- 手机配对页原先固定提示 Windows；改成桌面应用，macOS 上的开机启动说明也按系统显示。

## 验收

先验证核心闭环：日志开始 → 等待输入 → 完成，在修改时间不更新和分批写入时仍正确；并发额度更新不回退任务。再验证 Pro 响应解析、未知错误分类、桌面双语、手机配对失效重试与失败刷新。

独立启动的 app-server 对其他进程的任务可能返回 notLoaded，不能据此判定结束。本轮不把它接成单一权威来源；日志没有新事件也不能证明任务已结束。

## 实测结果与边界

- 本机 211 个会话文件：首次扫描约 1575 毫秒，缓存后的检查约 9 毫秒。新文件每 5 秒发现一次，旧文件内容按每秒检查；速度会随磁盘与会话数量变化。
- 构建、Rust 状态测试、网页交互测试覆盖了断线重连、旧配对失效、失败验收、英文窄屏、旧数据刷新，以及修改时间不变、记录分批写入、任务与额度并发更新。
- 没有新事件时，只能显示“状态待确认”，不能推断对话已经结束。未在 macOS 真机或已安装发行版上进行本轮验证；源代码改动尚未打包发布。
- 这次是针对确认过的可靠性与体验问题的修复。未来 Codex 协议仍可能变化，遇到未知响应时会显示可用性错误并保留上次数据，无法保证所有未来版本都无需适配。
