# 固定配对码与移动端同步设计

## 目标

让同一 Wi‑Fi 下的手机和 Kindle 首次输入四位配对码即可连接，之后由浏览器记住设备令牌并自动连接；同时保证网页不会用较旧的 HTTP 快照覆盖较新的实时状态。

## 方案

Windows 端在应用数据目录保存一次生成的四位数字配对码和一个随机的长期会话令牌。配对码只用于 `POST /api/pair` 换取会话令牌，详情页显示四位码和网页入口；网页将会话令牌保存到当前设备的 `localStorage`。重置配对时重新生成两者，旧设备立即失效。

网页 API 使用 `Cache-Control: no-store` 和 Bearer 会话令牌；WebSocket 仍通过查询参数传递令牌。网页端维护唯一 WebSocket，HTTP 首次快照与实时快照都按 `changed_at` 单调递增应用，断线时只显示最后一份已确认快照并自动重连。

## 安全与失败提示

四位码只在局域网首次配对使用，不作为长期凭据；长期访问使用随机令牌。服务仍只监听局域网端口，配对失败返回明确提示。令牌失效时网页清除本地令牌并回到配对页，不显示旧数据为最新状态。

## 验收标准

- 关闭并重新打开 Windows 应用后，四位配对码不变。
- 手机首次输入四位码后刷新或重新打开网页，无需再次输入即可看到最新快照。
- HTTP 快照较旧时不会覆盖 WebSocket 已推送的新额度、任务或 Token。
- WebSocket 断线只创建一个重连计时器，恢复网络后能自动恢复。
- 配对接口、令牌持久化、旧快照过滤和移动网页流程有自动化测试。
