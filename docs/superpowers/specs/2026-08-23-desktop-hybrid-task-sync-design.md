# Codex Desktop 混合任务状态同步设计

## 目标

在不修改现有 UI 结构的前提下，让悬浮窗监控正在运行的 Codex Desktop：黄色、绿色和灰色从本地结构化状态库获得；红色仅由可信 Hook 或 Windows 辅助功能检测到的真实授权控件产生；额度、Token 与标题继续沿用现有数据源。

## 数据源与优先级

1. Hook 事件：最高优先级。Desktop 恢复分发后，按 `session_id + turn_id` 驱动运行、待批准和完成状态。
2. Windows UI Automation：只补充当前 Codex Desktop 中真实存在的授权控件，生成或维持红色；控件消失后恢复数据库中的轮次状态。
3. `thread_history_1.sqlite`：读取 `thread_turns` 的结构化 `inProgress`、`completed`、`interrupted` 状态，作为 Desktop 黄色、绿色、灰色的主要来源。
4. 独立 app-server 与 rollout 文件：只更新额度、Token、标题、当前内容等元数据，不得覆盖更高优先级的任务状态。

## 状态规则

- 黄色：同一线程最新轮次为 `inProgress`，且没有更高优先级的待批准状态。
- 红色：收到可信 `PermissionRequest` Hook，或 UI Automation 在 Codex 窗口中检测到真实授权按钮组。
- 绿色：同一线程最新轮次显式变为 `completed`，保持到用户点击“已验收”。
- 灰色：没有可确认的活动、待批准或未验收完成任务；历史状态不伪装为实时状态。

旧轮次完成事件不能结束同一线程的新轮次。辅助功能未能关联具体线程时，只显示通道受限，不得把任意任务猜成红色。

## 实时性与隐私

- 状态库每 750 毫秒只读查询一次，目标是在数据库提交后 1 秒内更新。
- UI Automation 每 750 毫秒检查 Codex 窗口控件，只读取窗口标题、控件类型、自动化 ID 和授权按钮名称；不读取聊天正文、提示词或命令内容。
- 数据库被占用或辅助功能不可用时保留最后成功数据，并显示真实通道状态。

## 界面一致性

`SnapshotStore.tasks` 是唯一任务列表。长条、详情页、网页端和状态计数全部直接从该列表计算，禁止各自轮询、缓存或过滤。

## 验收标准

- Desktop 中同时存在多个 `inProgress` 轮次时，详情页全部显示黄色，长条数量完全一致。
- 一个轮次完成后变绿并保持到验收；验收后隐藏。
- 真实授权控件出现后约 1 秒内变红，控件消失后恢复黄色或绿色。
- Hook 恢复后自动成为最高优先级，轮询不能清除红色或结束较新的轮次。
- 读取失败时明确显示通道受限，不伪装成同步正常。
