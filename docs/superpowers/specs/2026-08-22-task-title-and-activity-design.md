# 任务标题与当前内容分离设计

## 目标

任务列表同时表达三个层次：Codex 会话标题、该会话当前用户任务的第一句话、任务状态。当前内容不能覆盖会话标题。

## 数据模型

- `TaskSummary.title` 只保存 Codex 会话标题。
- 新增可选字段 `TaskSummary.activity`，保存 rollout 中最近识别到的用户任务首句。
- 当 app-server 没有正式会话标题时，标题回退为“Codex 对话”；`activity` 仍显示首句。
- 生成上下文标签（包括 `<recommended_plugins>`、`<codex_delegation>` 和 `<codex_...>`）不能作为会话标题。

## 展示

桌面端和网页端详情任务行统一显示：标题 → 当前内容 → 状态。需要批准时在状态下方显示等待原因，并保留批准/拒绝按钮；已完成时保留可验收按钮。长条界面只显示颜色点和数量，不改变现有逻辑。

## 验证

- Rust 测试验证标题与 activity 分离，以及生成上下文不会成为标题。
- 前端测试验证详情行同时显示会话标题、当前内容和状态。
- Web UI 测试验证同一快照下的任务显示一致。
