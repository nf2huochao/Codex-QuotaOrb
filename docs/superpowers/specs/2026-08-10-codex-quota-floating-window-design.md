# Codex 额度悬浮窗设计规格

## 目标

构建一个 Windows 常驻工具，让用户一眼看到 Codex 本周剩余额度，并在需要时查看额度详情、当前任务状态和本日 Token 消耗。第一阶段只服务个人使用和同一 Wi‑Fi 内的设备，不把账号数据上传到云端。

## 已确认的产品范围

- Windows：系统托盘图标、桌面悬浮球、开机自启、显示/隐藏悬浮球、手动更新、退出。
- 悬浮球：始终置顶、可拖动、紧凑的灵动岛长条；三段等宽且尽量无空档。
  - 左段：带杏色/鼠尾草绿圆环的“本周剩余”百分比。
  - 中段：任务状态灯和数量，例如“3 个任务执行中”。
  - 右段：本日 Token 总量。
- 详情：点击整条悬浮球后原位展开；显示下次重置时间、当前套餐、可用重置机会、今日 Token、任务列表、最后更新时间和更新按钮。
- 数据刷新：自动每 2 分钟读取一次；更新按钮立即读取一次。
- 任务状态：灰色=没有活跃任务；红色=需要回复、确认或授权；黄色=正在执行；绿色=任务完成、可以验收。绿色任务保留到用户点击“已验收”；该动作只隐藏本地仪表盘记录，不归档、不删除 Codex 原任务。
- 跨设备：Windows 端提供同一 Wi‑Fi 可访问的响应式网页/PWA；iPhone 和 Kindle 第一阶段使用网页，后续再封装原生 iOS App。

## 视觉设计

整体采用“扁平几何 + 轻拟物凹凸”的极简方向：形状和文字保持扁平清晰，使用外凸高光、内凹阴影和轻量投影制造层次，不做复杂插画和渐变堆叠。

- 奶油白：`#ebe4d6`，用于浮球主体和详情卡片。
- 鼠尾草绿：`#bdcfa2`，用于环境底色、柔和背景和进度环剩余段。
- 杏色：`#ddb480`，用于额度进度和主要强调。
- 状态色只用于状态灯和对应文字，保证红、黄、绿含义明确。
- 长条采用圆角胶囊结构，三段等宽；移动端窄屏自动变为三行但保留同一信息顺序。

## 技术架构

### Windows 采集与展示端

使用 Tauri 作为桌面壳，Rust 负责进程管理、系统托盘、窗口置顶/拖动、开机自启和本地 HTTP 服务；前端使用 HTML/CSS/TypeScript 渲染悬浮球、详情面板和网页仪表盘。Tauri 体积小，适合常驻工具；不使用 Electron，避免常驻内存过大。

### Codex 数据适配层

应用启动本机 `codex app-server` 子进程，通过 JSON-RPC 读取 Codex 自身状态，不直接读取、保存或展示登录令牌。主要数据来源为：

- `account/rateLimits/read`：额度窗口、剩余百分比、重置时间、套餐类型、重置机会。
- `account/usage/read`：本日及历史 Token 使用汇总。
- app-server 的线程/回合状态和事件：任务标题、当前阶段、需要用户处理的状态、完成状态及可用的 Token 统计。

接口属于 Codex 当前实验能力，适配层必须隔离协议细节，保存运行时 schema 版本；接口不可用或字段变化时进入明确错误状态，不使用未经标注的旧数据。

### 同一 Wi‑Fi 网页端

Windows 端启动局域网 HTTP/WebSocket 服务，网页和 PWA 只连接该服务。默认只监听局域网地址，首次连接使用一次性配对码；服务不开放公网、不把数据发送到第三方。网页端只负责展示和本地“已验收”状态，不允许执行归档、删除、授权或其他 Codex 写操作。

### iPhone 与 Kindle

第一阶段通过响应式网页访问；页面提供轻量 PWA 入口和基础 HTML 回退，避免 Kindle 浏览器不支持完整 PWA 时无法查看。原生 iOS App 作为第二阶段，只复用同一网页 API 和数据模型，不重新实现额度读取。

## 数据状态与异常处理

每个数据快照包含 `fetchedAt`、`source`、`schemaVersion` 和状态 `fresh | stale | error | unauthenticated`。

- `fresh`：最近一次成功读取不超过 15 分钟，正常显示。
- `stale`：超过 15 分钟未成功读取；可以显示最后一次值，但必须变灰并标注“数据已过期·最后更新于…”。
- `error`：本次读取失败且没有可用快照；显示 `--`、错误原因和“立即更新”。
- `unauthenticated`：Codex 未登录或登录失效；提示在 Codex 中登录，不显示伪造的 0% 或旧套餐。
- app-server 退出、协议版本不兼容、局域网连接断开分别显示可理解的短提示，并保留重试入口。

任务状态映射由单独规则模块完成：等待用户回复/确认/授权优先为红色；执行中为黄色；已完成但未验收为绿色；没有任何活跃任务为灰色。状态更新只改变展示，不触发 Codex 写操作。

## 隐私与安全

- 账号认证由 Codex 自身进程处理，应用不读取 auth 文件、不记录令牌、不写入日志。
- 局域网服务使用随机配对码和本地会话令牌；日志只记录时间、错误类别和协议版本，不记录任务正文或敏感路径。
- 默认只允许同一 Wi‑Fi 访问；外网访问、云端同步、多用户账号不在第一阶段范围。
- “立即更新”和“已验收”是唯一的展示层操作；不提供自动授权、发送消息、删除、归档或消费重置机会的按钮。

## 测试与验收

### 自动化测试

- 额度响应解析：百分比、重置时间、套餐、重置机会和缺失字段。
- Token 汇总解析：本日总量、任务拆分、空值和异常值。
- 状态映射：红/黄/绿/灰四种规则及优先级。
- 新鲜度计算：2 分钟轮询、15 分钟过期、首次失败和恢复成功。
- 协议版本兼容：模拟旧字段、未知字段、进程退出和超时。
- PWA/API：同一 Wi‑Fi 下的配对、断线重连和只读权限。

### 手工验收

- Windows 托盘图标、开机自启、显示/隐藏、退出和始终置顶行为。
- 悬浮球三段等宽、拖动、点击原位展开、窄屏布局和轻拟物阴影。
- iPhone Safari、桌面浏览器和 Kindle 浏览器可读性；数据断开时能看到过期/失败提示。
- 使用真实 Codex 账号验证额度、任务状态和 Token 数值；刷新后不出现旧数据伪装成最新状态。

## 分阶段交付

第一阶段：Windows Tauri 应用、系统托盘、紧凑悬浮球、本机 app-server 适配、2 分钟刷新、异常状态、局域网只读网页/PWA。

第二阶段：iPhone 原生外壳、设备配对体验优化、安装包签名和检查更新；继续复用第一阶段网页 API 和数据模型。

不在本规格范围内：公网部署、云端账号、多用户权限、跨设备历史同步、自动执行 Codex 写操作、公开发布渠道。

## 成功标准

用户无需打开 Codex 窗口，就能在 Windows 悬浮球中看到真实的本周剩余百分比、任务状态数量和本日 Token 总量；点击后能看到重置时间、套餐和重置机会；任何数据过期或读取失败都明确可见；iPhone 和 Kindle 在同一 Wi‑Fi 下能通过网页查看同一份只读数据。

## 第二版交互深化（2026-08-11）

本版把“悬浮球”从视觉称呼落实为三层状态机，保留已确认的方案 1 奶油白、鼠尾草绿、杏色视觉基准：

- `ball` 收起态：约 78×78 的圆角悬浮球，只显示额度环和百分比；任务状态以环外状态色提示，仍然保持可拖动。
- `summary` 状态态：第一次点击后展开为方案 1 的三段等宽胶囊，依次显示本周额度、任务状态、本日 Token。
- `details` 详情态：再次点击三段胶囊后原位展开详情面板，显示重置时间、套餐、重置机会、Token、更新时间、任务列表和刷新按钮。

点击与拖动采用 6px 阈值：指针位移小于 6px 才触发下一层，超过 6px 只移动窗口，避免拖动误展开。状态切换使用 180ms 外层过渡和 240ms 数据环过渡；原生窗口高度跟随内容做同一缓动，不在窄窗口中制造滚动条。

Rust 的 `SnapshotStore` 每次发布快照时发出 `snapshot-updated` 事件，前端立即重绘；2 分钟轮询继续作为数据读取兜底。托盘“立即更新”和详情“立即更新”共用同一刷新流程，按钮在请求期间显示“正在更新”，成功或失败都明确呈现更新时间或错误状态。
