# 内部会话混入任务列表：根因与修复

## 已确认的故障链

现场运行版本为1.0.6。已保存的快照中，两条“suggested next user message”记录来自hook，既无对应本地rollout，也不在普通线程元数据表中。此次问题与Guardian日志过滤是否生效无关。

此前链路存在三个缺口：

- Hook身份认证只认证发送方；所有UserPromptSubmit都直接变成Running，不验证是否用户会话。
- 任务合并把hook排在最高优先级，且本地扫描只清理local-session来源；内部hook没有对应日志也不会因此被清除。
- Guardian过滤只在一个读取器内，没有快照统一准入校验；Hook、缓存或其它来源可以绕过。

## 本次统一边界

现有有界增量扫描同时识别session_meta来源，建立普通会话ID集合。已知客户端下的user、automation、正式agent_created_thread/agent_forked_thread、composer_link和realtime_voice保留；已知旧客户端无thread_source的历史格式兼容。所有实现subagent、未知客户端/类型、缺失或无效来源均不自动进入普通列表；不根据标题、正文、role=user、Hook认证或数据源优先级授予准入。

生产SnapshotStore从空任务列表启动，所有publish/update在计算状态数及向HTTP/WebSocket/桌面/缓存输出之前统一过滤。来源集合更新与旧任务清除在同一状态锁下完成；同集合心跳不会额外刷新界面。周期扫描和手动刷新都接入同一来源规则。只有测试可使用原不受限构造器。

没有新增SQLite运行依赖，没有扩大日志读取预算，没有修改Hook配置、配对、权限审批执行结果或任何运行服务。

## 验证与适用边界

完整后端测试：97 passed / 0 failed / 2 ignored。跳过项是既有真实日志读取/计时测试，不代表失败或新覆盖。

非测试生产库检查 cargo check --lib --locked --offline 通过；保留原有未使用代码警告。补丁差异检查通过。前端代码未变化，没有重复无关的UI套件。

核心回归直接调用生产metadata读取器，随后通过真实Axum路由（合成HTTP请求，无真实服务）验证Hook开始→结束→重复开始→snapshot：内部新类型与无来源建议请求均不可见；真实用户对话包含完全相同文字仍保留。另验证正式团队/自动化来源、未知未来类型、缓存与高权重来源复活、空来源集合移除及计数一致。原大日志有界读取、部分行与mtime不变增量回归均通过。

现场仅额外抽查普通用户、正式创建团队和分叉会话的首条元数据，与准入规则一致；所抽自动化任务文件已不存在，因此不宣称自动化现场运行已验。

新普通会话可能等待最多一次目录发现间隔（5秒，另加扫描耗时）。没有可验证本地来源的远程会话暂不猜测展示。未知未来格式会先隐藏而非误报；需要新增兼容时应明确扩展来源契约。此修复是准入隔离，不是安全认证系统，也不能辨别客户端错误标注为真实用户来源的内部请求。

本次没有发布新版本或替换本机1.0.6；不把测试通过写成运行界面已经生效。
